`io.select.multiple()` asks to pick several options and returns the chosen options themselves: `{ value, label }` objects, enum members or records from your database. The drop-down and the chosen options sit in one frame: each pick is listed under the drop-down, one per row, and the × on its right takes it back. Provided by the `@awaitio/select-multiple` package.

## Install

```bash
npm install @awaitio/select-multiple
```

## Setup

Register it under the key you want in `io`, see [Input components](/core/input-components):

```ts app.ts {5}
import { selectMultiple } from '@awaitio/select-multiple';

export const app = new AwaitIO({
  // name, actionsDirectory, theme, secret, users…
  components: { select: { multiple: selectMultiple } },
});
```

## Usage

```ts
const channels = await io.select.multiple('Tell them by', {
  options: [
    { value: 'email', label: 'Email' },
    { value: 'slack', label: 'Slack' },
    { value: 'sms', label: 'SMS' },
  ],
  defaultValue: ['email'],
  maxSelections: 2,
  helpText: 'Leave it empty to change the role quietly.',
});
// channels is [{ value: 'email', label: 'Email' }]
```

Options can be records, identified and named by `key` and `label`; the defaults can be their keys:

```ts
const admins = await io.select.multiple('Admin users', {
  options: await prisma.user.findMany(),
  key: (user) => user.id,
  label: (user) => user.email,
  defaultValue: integrator.admins.map((admin) => admin.id),
});
// admins is a list of the User records
```

The options stay on the server; the browser gets only their labels and answers with the positions of the chosen ones.

## Props

| Prop            | Type                 | Required | Description                                                                                                 |
| --------------- | -------------------- | -------- | ----------------------------------------------------------------------------------------------------------- |
| `options`       | `TOption[]`          | Required | What to choose from: strings, numbers, `{ value, label }` objects or any records. The drop-down offers those not chosen yet. |
| `key`           | `(option) => string \| number` | Optional | What identifies an option. Required for records without `value`; defaults to the string, number or `value`. |
| `label`         | `(option) => string` | Optional | What the drop-down shows. Required for records without `label`; defaults to the string, number or `label`. |
| `defaultValue`  | keys or `TOption[]`  | Optional | The options chosen at the start: their keys (ids are enough) or the options themselves. Keys that are not among the options are left out and reported in the server log. |
| `minSelections` | `number`             | Optional | At least this many must be chosen. By default none.                                                         |
| `maxSelections` | `number`             | Optional | At most this many may be chosen; the drop-down stops offering more.                                         |
| `helpText`      | `string`             | Optional | Secondary text under the field.                                                                             |
| `disabled`      | `boolean`            | Optional | Shows the starting value without letting it change; the handler gets that value whatever the browser sends. |

## Optional

The field is required. Chain `.optional()` to let it stay empty; the handler then gets the options or `undefined`, see [Optional fields](/core/input-components#optional-fields).

```ts
const channels = await io.select.multiple('Channels', { options: allChannels }).optional();
```

## Returns

The chosen options themselves, typed by `options`, in the order of the options, not the order they were picked.

## Built-in validation

The server checks every answer, so a crafted request cannot slip in other values:

| When                                       | Message                                     |
| ------------------------------------------ | ------------------------------------------- |
| Fewer than `minSelections`                 | `<label>: choose at least <minSelections>.` |
| More than `maxSelections`                  | `<label>: choose at most <maxSelections>.`  |
| A value that was not offered, or one twice | `<label>: choose from the options only.`    |

## Custom validation

Chain `.validate()` for a check of your own. It runs on the server after the checks above, gets the value the handler would get and returns a message to show under the field, or nothing when the value is fine; see [Custom validation](/core/input-components#custom-validation).

```ts
const channels = await io.select.multiple('Notify by', { options: channelOptions }).validate((channels) => {
  return channels.some((channel) => channel.value === 'sms') && !user.phone ? 'Add a phone number before choosing SMS.' : undefined;
});
```
