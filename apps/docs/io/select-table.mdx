`io.select.table()` shows records as a table with a radio or a checkbox in front of each row and returns the rows that were picked. Provided by the `@awaitio/select-table` package.

<Frame>
  <img src="/images/io-select-table.png" alt="A User table with Name, email and Account columns, a filter and paging above it and a radio in front of every row, Aiko Tanaka picked" />
</Frame>

The table has the same filter, pager and value formatting as [`io.display.table`](/io/display-table).

## Install

```bash
npm install @awaitio/select-table
```

## Setup

Register it under the key you want in `io`, see [Input components](/core/input-components):

```ts app.ts {5}
import { selectTable } from '@awaitio/select-table';

export const app = new AwaitIO({
  // name, actionsDirectory, theme, secret, users…
  components: { select: { table: selectTable } },
});
```

## Usage

```ts
const [user] = await io.select.table('User', {
  data: await prisma.user.findMany({ include: { account: true } }),
  columns: [{ label: 'Name', accessorKey: 'name' }, 'email', { label: 'Account', renderCell: (row) => row.account.name }],
});
```

`user` is the record itself, typed like the records in `data`. The columns are written as in [Display Table](/io/display-table#columns): a key, `{ label, accessorKey }` or `{ label, renderCell }`, and `renderCell` can return a colored label or a link the same way.

## Props

| Prop            | Type                                              | Required | Description                                                                                                                                                      |
| --------------- | ------------------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `data`          | `TRow[]`                                          | Required | The records to pick from; none shows `emptyText`, see [An empty table](#an-empty-table).                                                                         |
| `columns`       | `(key \| { label, accessorKey?, renderCell? })[]` | Required | The columns, see [Display Table](/io/display-table#columns).                                                                                                     |
| `defaultValue`  | `TRow[]`                                          | Optional | Items of `data` picked at the start: the same objects, or copies with the same values.                                                                           |
| `minSelections` | `number`                                          | Optional | At least this many rows, or all of them when there are fewer. Defaults to 1.                                                                                     |
| `maxSelections` | `number`                                          | Optional | At most this many rows. Defaults to 1, which shows radios instead of checkboxes; with more, a pick past the limit is ignored, see [Several rows](#several-rows). |
| `pageSize`      | `number`                                          | Optional | Rows per page. Defaults to 10.                                                                                                                                   |
| `emptyText`     | `string`                                          | Optional | Shown instead of the table when there are no rows. Defaults to _Nothing to show._                                                                                |
| `helpText`      | `string`                                          | Optional | Secondary text under the table.                                                                                                                                  |
| `disabled`      | `boolean`                                         | Optional | Shows the starting value without letting it change; the handler gets that value whatever the browser sends.                                                      |

## Several rows

With `maxSelections` above 1 every row gets a checkbox, and a _…_ menu next to the pager picks rows in bulk: _Select all_ picks every row that matches the filter, on all pages, and _Clear all_ unpicks them. The menu offers only what would change something: no _Select all_ when every matching row is picked or the rows would go past `maxSelections`, no _Clear all_ when none is picked.

```ts
const notified = await io.select.table('Users to notify', {
  data: users,
  columns: [{ label: 'Name', accessorKey: 'name' }, 'email'],
  minSelections: 0,
  maxSelections: users.length,
  pageSize: 5,
});
```

## An empty table

`data` can be empty, e.g. for an account without devices. The person then sees `emptyText` instead of the table and continues with nothing picked: `minSelections` never asks for more rows than the table has, so the handler gets `[]`.

```ts
const devices = await io.select.table('Devices to restart', {
  data: account.devices,
  columns: ['name', 'status'],
  maxSelections: 50,
  emptyText: 'This account has no devices.',
});
```

## Optional

The field is required. Chain `.optional()` to let it stay empty; the handler then gets `TRow[] | undefined`, see [Optional fields](/core/input-components#optional-fields).

```ts
const notified = await io.select.table('Users to notify', { data: users, columns: ['name', 'email'], maxSelections: 5 }).optional();
```

## Returns

`TRow[]`: the picked items of `data` themselves, the same objects the handler passed in, in the order they were picked: every field, `Date`s and nested objects included. Only the cells go to the browser; it answers with the positions of the picked rows, the server checks them and hands over the items at those positions.

```ts
const devices = await io.select.table('Devices to delete', {
  data: await prisma.device.findMany({ include: { account: true } }),
  columns: ['name', { label: 'Account', renderCell: (device) => device.account.name }],
  maxSelections: 50,
});

await prisma.device.deleteMany({ where: { id: { in: devices.map((device) => device.id) } } });

return devices.map((device) => `${device.name} (${device.account.name})`);
```

## Built-in validation

The server checks every answer, so a crafted request cannot slip in another row:

| When                            | Message                                        |
| ------------------------------- | ---------------------------------------------- |
| No row picked, by default       | `<label>: pick a row.`                         |
| Fewer than `minSelections`      | `<label>: pick at least <minSelections> rows.` |
| More than `maxSelections`       | `<label>: pick at most <maxSelections> rows.`  |
| A row that was not in the table | `<label>: pick rows from the table only.`      |

## Custom validation

Chain `.validate()` for a check of your own. It runs on the server after the checks above, gets the value the handler would get and returns a message to show under the field, or nothing when the value is fine; see [Custom validation](/core/input-components#custom-validation).

```ts
const [user] = await io.select.table('User to remove', { data: users, columns: ['name', 'role'] }).validate((rows) => {
  return rows.some((row) => row.role === 'admin') ? 'Admins cannot be removed here.' : undefined;
});
```
