AwaitIO has no route table. You pass a folder to `new AwaitIO()` as `actionsDirectory` and every file in it becomes an action, with its path as the URL and its folders as the navigation.

```ts app.ts {5}
import { join } from 'path';

export const app = new AwaitIO({
  name: 'Internal tools',
  actionsDirectory: join(__dirname, 'actions'),
  // theme, secret, users, components…
});
```

## Two ways to lay it out

Start flat and sort the actions into folders once the list gets long. Moving a file changes its URL, so links to it change too.

### Minimal setup without folders

Every action sits directly in `actions/`, as in the [Quickstart](/quickstart):

```text
actions/
├── createAccountAction.ts → /actions/create_account
├── refundPaymentAction.ts → /actions/refund_payment
└── resetPasswordAction.ts → /actions/reset_password
```

The home page lists them as cards, without tabs. Enough for a handful of tools.

### Folders with tabs and a file browser

Put the actions into folders and the folders become the navigation:

<Frame caption="The Inputs folder of the Components tab in the demo app: the Dates subfolder as a card, then the actions of Inputs itself.">
  <img src="/images/routing-tabs.png" alt="The action list with the tabs Accounts, Billing, Components, Support and Users; the Inputs folder of Components shows a Dates folder card above its action cards" />
</Frame>

- **Top-level folders are tabs.** Each folder directly in `actions/` becomes a tab in the second row of the header (_Accounts_, _Billing_, _Components_, _Support_, _Users_) at `/groups/<folder>`, e.g. `/groups/accounts`. There is no tab with everything: `/` opens the first tab.
- **A folder shows only what is directly in it**, like a file browser: its subfolders as cards first, then its own actions. Open a subfolder card to see what is inside: `/groups/components/inputs/dates`. A folder with a page (see below) lists them in a column on the left instead and shows the page next to them.
- **Breadcrumbs.** Inside a subfolder and above an action, _← Actions › Components › Inputs_ links back to each folder. Leaving a run that is still going cancels it.

## The path is the URL

The slug of an action is its path in the folder, each part in snake_case. This is part of the demo app, each file with its URL:

```text
actions/
├── accounts/
│   ├── index.ts                   → /groups/accounts (a page)
│   ├── createAccountAction.ts     → /actions/accounts/create_account
│   └── extendTrialAction.ts       → /actions/accounts/extend_trial
├── billing/
│   ├── index.ts                   → /groups/billing (a page)
│   └── refundPaymentAction.ts     → /actions/billing/refund_payment
├── components/
│   ├── index.ts                   → /groups/components (a page)
│   ├── confirmAction.ts           → /actions/components/confirm
│   └── inputs/
│       ├── inputTextAction.ts     → /actions/components/inputs/input_text
│       └── dates/
│           └── inputDateAction.ts → /actions/components/inputs/dates/input_date
├── support/
│   └── replyToTicketAction.ts     → /actions/support/reply_to_ticket
└── users/
    ├── index.ts                   → /groups/users (a page)
    └── changeRoleAction.ts        → /actions/users/change_role
```

- Name an action's file after its const, which ends in `Action`: `export const createAccountAction` lives in `createAccountAction.ts`. The URL leaves the suffix out, so the slug is `create_account`.
- `createAccountAction.ts`, `create_account.ts` and `create-account.ts` all give the slug `create_account`, and folders follow the same rule. Two files that end up with the same slug stop the app at start.
- Folders go as deep as you need.
- The handler reads the slug as `ctx.action.slug`: `accounts/create_account`.
- The list shows names, not paths: the URL is what you link to, not something people read.

## One file, one action

Each file exports one `app.defineAction(...)`, as a named or a default export:

```ts actions/accounts/createAccountAction.ts
import { app } from '../../app';

export const createAccountAction = app.defineAction({
  name: 'Create account',
  handler: async ({ io }) => {
    const company = await io.input.text('Company name');

    return `${company} has an account.`;
  },
});
```

A file that exports no action, or more than one, stops the app at start with an error naming the file. Action files import `app` for their typed `io`, so keep `new AwaitIO()` in its own `app.ts`; AwaitIO imports the action files itself.

**Skipped:** files and folders whose name starts with `_` or `.`, `*.test.ts`, `*.spec.ts` and `*.d.ts`. Put helpers that are not actions in a folder like `actions/_shared/`, or outside the actions folder.

## index.ts is the folder

`index.ts` stands for its folder. It can export either:

- **a page** with `app.definePage()`: the folder then shows its subfolders and actions in a column on the left and the page on the right, such as a table of all users. In the demo, `users/index.ts` is one.
- **an action** with `app.defineAction()`: it gets the folder's slug (`billing/index.ts` is at `/actions/billing`) and leads the folder's actions.

The top level of `actions/` has no index file; an `index.ts` there stops the app at start.

## Names and order

- **Every action needs a `name`**: the action list and the run page show it. An action without one stops the app at start.
- **Folders are named after themselves**, in words: `billing` reads _Billing_, `auditLogs` and `audit_logs` both read _Audit logs_.
- **The order** is alphabetical by file name. In the list, a folder's subfolders come before its actions, and its `index.ts` leads the actions.

## Unlisted actions

An action that only makes sense for one record, such as editing a user picked in a table, can stay out of the list. Pass `unlisted: true`: it is not in the action list or in its folder's column, but it still runs from its URL, from [`ctx.redirect()`](/ctx/redirect) and from a table's row menu:

```ts actions/users/editUserAction.ts
export const editUserAction = app.defineAction({
  name: 'Edit user',
  unlisted: true,
  params: z.object({ id: z.string() }),
  handler: async ({ io, ctx }) => {
    // …
  },
});
```

It is not a permission: anyone who can log in can still open its URL.

## URLs of a run

| URL                       | What it shows                                                                      |
| ------------------------- | ---------------------------------------------------------------------------------- |
| `/`                       | The list of actions, or the first tab when there are folders.                      |
| `/groups/<folder>`        | One folder: its subfolders and its own actions.                                    |
| `/actions/<slug>`         | Starts a new run of the action.                                                    |
| `/actions/<slug>/<runId>` | One run, its current step or its result. Only the user who started it can open it. |
| `/actions/<slug>?id=42`   | Starts a run with `ctx.params` `{ id: '42' }`.                                     |

## When you compile

AwaitIO loads the action files when `listen()` runs, so the folder must exist next to the compiled server with the compiled files in it. `tsc` keeps the layout; a bundler that produces a single file drops it.
