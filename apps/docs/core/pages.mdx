A folder's `index.ts` can export a page instead of an action, see [Routing](/core/routing). The folder then shows its subfolders and actions in a column on the left and the page on the right. A page puts **display components** (a table, tiles…) into a **layout**. It only displays, so there is no form and no Continue button.

A page needs the display components it shows registered in `components`, see [Display components](/core/display-components), and a layout to put them in, see [Layouts](#layouts).

## Write a page

Export `app.definePage()` from the folder's `index.ts`. The handler returns a layout with the display components in it:

```ts actions/users/index.ts
import { app } from '../../app';

export const usersPage = app.definePage({
  description: 'Everyone who can be messaged.',
  handler: async ({ io, ctx }) => {
    const users = await prisma.user.findMany();

    return io.layout.basic({
      title: 'Users',
      children: [io.display.metadata(null, { items: [{ label: 'Users', value: users.length }] }), io.display.table('All users', { data: users, columns: ['name', 'email'] })],
    });
  },
});
```

- Every display component takes a label, shown as the heading above it (`null` for none), and its props.
- Returning just the array, `return [io.display.table(…)]`, puts it into the layout registered as `basic`.
- Props are typed by each component's schema, and the server checks them again before they reach the browser: props that do not fit show an error instead of the page.
- The handler runs every time someone opens the folder; nothing is kept between visits.
- The handler gets `ctx` like an action: [`ctx.user`](/ctx/user) is who opened the page and `ctx.params` the query string of the link (`/groups/users?role=admin`), see [Params](#params). `ctx.page.slug` is the folder the page stands for: `users`.
- `app.definePage()` belongs only in a folder's `index.ts`; anywhere else it stops the app at start.
- Its const ends in `Page`, `usersPage`, as an action's ends in `Action`; the file stays `index.ts`.

## Params

Describe the query string the page expects with a zod schema in `params`, as an [action does](/ctx/params). The server checks the link against it before the handler runs, and `ctx.params` gets the parsed, typed value:

```ts actions/users/index.ts {4}
import { z } from 'zod/v4';

export const usersPage = app.definePage({
  params: z.object({ role: z.enum(['admin', 'member']).optional() }),
  handler: async ({ io, ctx }) => {
    // ctx.params is { role?: 'admin' | 'member' }
    const users = await prisma.user.findMany({ where: { role: ctx.params.role } });

    return [io.display.table('Users', { data: users, columns: ['name', 'email', 'role'] })];
  },
});
```

- A link that does not fit shows _The link does not fit this page_ with what is wrong, instead of the page.
- Without `params`, `ctx.params` is every key of the query string as a string.
- The schema also types `usersPage.route()`, the link an action opens with [`ctx.redirect()`](/ctx/redirect#redirect-to-a-page): `usersPage.route({ params: { role: 'admin' } })`.

## Unlisted pages

A page that only makes sense for one record, such as the detail of a user opened from a table or after an action, can stay out of the navigation. Pass `unlisted: true`: its folder is not a tab or a folder card because of the page, but the page still opens from its URL and from [`ctx.redirect()`](/ctx/redirect#redirect-to-a-page):

```ts actions/userDetail/index.ts {2}
export const userDetailPage = app.definePage({
  unlisted: true,
  params: z.object({ id: z.string() }),
  handler: async ({ io, ctx }) => {
    // …
  },
});
```

- A folder with listed actions is still shown for them, and opening it shows the page as usual.
- It is not a permission: anyone who can log in can still open its URL.

## Layouts

The handler returns the display components inside a layout, the frame that places them. Every layout is a package registered in `layouts`, the basic one too:

```ts app.ts {5}
import { layoutBasic } from '@awaitio/layout-basic';

export const app = new AwaitIO({
  // name, actionsDirectory, theme, secret, users, components…
  layouts: { basic: layoutBasic },
});
```

See [Layout components](/core/layout-components) for the layouts there are and how to write your own.
