What changed in each release, grouped by part of AwaitIO. Every package has its own version and its own `CHANGELOG.md` on npm.

<Update label="1.4.0" description="November 11, 2026" tags={["Core", "Components", "Theme"]}>
  <img src="/images/changelog/1.4.0.png" style={{ marginTop: 0, borderRadius: 12 }} alt="AwaitIO 1.4.0 release: awaitio with the order option for actions and pages, @awaitio/display-table, @awaitio/layout-basic, @awaitio/display-link, @awaitio/theme-default and every component at 1.4.0" />

  ## Core

  `awaitio@1.4.0`

  - [`order`](/core/routing#order) on `app.defineAction()` puts an action higher in its folder: actions with an `order` come first, lower numbers first, the rest stay alphabetical. On a folder's [`index.ts`](/core/pages#order) it orders the folder's tab or card the same way.
  - A table cell's `route` takes a page's `page.route()` next to an action's route and opens the page in the same tab.
  - A folder with a page and nothing to list next to it, such as only unlisted actions, no longer shows an empty column with _No actions here._; the page takes the full width.
  - `awaitio/ui` exports `routeSchema`, `pageRouteSchema`, `routeHref` and the `Route` and `PageRoute` types, for components of your own that link to actions and pages.

  ## Components

  `@awaitio/*@1.4.0`, every component

  - [`io.display.table`](/io/display-table#row-menu): `rowMenuItems` take a page's `page.route()` next to an action's route.
  - [`io.layout.basic`](/io/layout-basic#menu-items): `menuItems` take a page's `page.route()` too, so a button next to the title can open a page.
  - [`io.display.link`](/io/display-link#link-into-the-app) takes a `route` to an action or a page instead of a `url`. It opens in the same tab and says the route's label.
  - Every other component moves to 1.4.0 with `awaitio`, without changes in behavior.

  ## Theme

  `@awaitio/theme-default@1.4.0`

  - Moves to 1.4.0 with `awaitio`, without changes in look.

  ## Migration guide

  From 1.3.0 to 1.4.0.

  <AccordionGroup>
    <Accordion title="awaitio">
      Nothing to change. Update `awaitio` and every `@awaitio/*` package to `^1.4.0` together: the 1.4.0 components use the new `awaitio/ui` exports and do not run with `awaitio@1.3`. Without `order`, actions, tabs and folders stay alphabetical, as before. Code of your own that reads a `TableCell`'s `route` now gets `Route`, an action's or a page's route: check `'action' in route` before reading `route.action`, or it no longer type-checks.
    </Accordion>
    <Accordion title="@awaitio/display-table">
      Nothing to change. `rowMenuItems` now returns `Route[]` instead of `ActionRoute[]`; a function typed as returning `ActionRoute[]` still fits.
    </Accordion>
    <Accordion title="@awaitio/layout-basic">Nothing to change. `menuItems` built with `action.route()` work as before.</Accordion>
    <Accordion title="@awaitio/display-link">Nothing to change. A link with `url` and `text` works as before; `text` is not allowed next to `route`, pass `route({ label })` instead.</Accordion>
    <Accordion title="@awaitio/*">Nothing to change.</Accordion>
    <Accordion title="@awaitio/theme-default">Nothing to change.</Accordion>
  </AccordionGroup>
</Update>

<Update label="1.3.0" description="November 10, 2026" tags={["Core", "Components", "Theme", "License"]}>
  <img src="/images/changelog/1.3.0.png" style={{ marginTop: 0, borderRadius: 12 }} alt="AwaitIO 1.3.0 release: awaitio with typed page links, unlisted pages and the head option, @awaitio/theme-default and every component at 1.3.0" />

  ## Core

  `awaitio@1.3.0`

  - A page takes a [`params`](/core/pages#params) schema like an action: the link is checked before the handler runs, `ctx.params` is typed, and a link that does not fit shows what is wrong instead of the page.
  - [`ctx.redirect()`](/ctx/redirect#redirect-to-a-page) can open a folder's page, with the link built by `page.route()` and its params typed by the page's schema.
  - [`unlisted: true`](/core/pages#unlisted-pages) keeps a page, such as the detail of one record, out of the tabs and folder cards. It still opens from its URL and from `ctx.redirect()`.
  - The new [`head`](/core/app#extra-tags-in-the-head) option of `new AwaitIO()` adds your own HTML to the end of every page's `<head>`, such as an analytics script or link preview tags.
  - [`listen()`](/core/listen) prints `AwaitIO server is running at http://localhost:<port>` once the port is open. `log: false` turns it off.

  ## Components

  `@awaitio/*@1.3.0`, every component

  - Every component moves to 1.3.0 with `awaitio`, without changes in behavior.

  ## Theme

  `@awaitio/theme-default@1.3.0`

  - Moves to 1.3.0 with `awaitio`, without changes in look.

  ## License

  All packages

  - Months of a Company License that were missed can be paid later, at once as a one-time sponsorship on GitHub Sponsors or as agreed at license@awaitio.com. Such a payment counts as the license for those months, not as a gift.

  ## Migration guide

  From 1.2.0 to 1.3.0.

  <AccordionGroup>
    <Accordion title="awaitio">
      Nothing to change. Update `awaitio` and every `@awaitio/*` package to `^1.3.0` together. Your server now prints its address once on start; when your own code already prints it, drop that line or pass `log: false` to `listen()`. A page without `params` gets `ctx.params` as strings, as before.
    </Accordion>
    <Accordion title="@awaitio/*">Nothing to change.</Accordion>
    <Accordion title="@awaitio/theme-default">Nothing to change.</Accordion>
    <Accordion title="License">Nothing to change. The new paragraph only adds a way to settle missed months.</Accordion>
  </AccordionGroup>
</Update>

<Update label="1.2.0" description="October 27, 2026" tags={["Core", "Components", "Theme"]}>
  <img src="/images/changelog/1.2.0.png" style={{ marginTop: 0, borderRadius: 12 }} alt="AwaitIO 1.2.0 release: awaitio, @awaitio/select-table, @awaitio/theme-default and every component at 1.2.0" />

  ## Core

  `awaitio@1.2.0`

  - Long values without spaces, such as a login link with a token, wrap inside their card and table instead of running out of it or scrolling sideways.
  - Items of the [theme](/core/theme)'s `RowMenu` block can run an `onClick` instead of linking to an `href`, and the block takes a `label` for screen readers.

  ## Components

  `@awaitio/*@1.2.0`, every component

  - [`io.select.table`](/io/select-table#several-rows) with several rows gets a _…_ menu next to the pager: _Select all_ picks every row that matches the filter, on all pages, and _Clear all_ unpicks them. It offers only what would change something and leaves out _Select all_ when the rows would go past `maxSelections`.
  - Every other component moves to 1.2.0 with `awaitio`, without changes in behavior.

  ## Theme

  `@awaitio/theme-default@1.2.0`

  - Draws the _…_ menu above the table and wraps long values inside cards and table cells.

  ## Migration guide

  From 1.1.0 to 1.2.0.

  <AccordionGroup>
    <Accordion title="awaitio">
      Nothing to change. Update `awaitio` and every `@awaitio/*` package to `^1.2.0` together, so the theme draws the new table menu.
    </Accordion>
    <Accordion title="@awaitio/select-table">
      Nothing to change: the call and its answer stay the same. With `maxSelections` above 1 the menu appears on its own.
    </Accordion>
    <Accordion title="@awaitio/theme-default">
      With `@awaitio/theme-default`, nothing to change. A theme of your own with its own `RowMenu` block has to draw items with `onClick` as buttons: `RowMenuItem` is now `{ label, href }` or `{ label, onClick }`, so code that reads `item.href` without checking for it no longer type-checks.
    </Accordion>
  </AccordionGroup>
</Update>

<Update label="1.1.0" description="October 22, 2026" tags={["Core", "Components", "Theme", "License"]}>
  <img src="/images/changelog/1.1.0.png" style={{ marginTop: 0, borderRadius: 12 }} alt="AwaitIO 1.1.0 release: awaitio, the new @awaitio/select-single-native, @awaitio/theme-default and every component at 1.1.0" />

  ## Core

  `awaitio@1.1.0`

  - Component and theme scripts take ReactDOM from the app instead of bundling their own copy.
  - The [theme](/core/theme) has a new `NativeSelect` block for the browser's own drop-down.

  ## Components

  `@awaitio/*@1.1.0`, every component, with the new `@awaitio/select-single-native@1.1.0`

  - Every package now shares its major and minor version with `awaitio`, so `@awaitio/*@1.1.x` goes with `awaitio@1.1.x`. The last number is each package's own and goes up with any change to it.
  - [`io.select.single`](/io/select-single) is a searchable drop-down. The new `clearable` option shows a × that empties the field again.
  - New [`io.select.singleNative`](/io/select-single-native) keeps the browser's own `<select>`, for short lists.

  ## Theme

  `@awaitio/theme-default@1.1.0`

  - Draws the searchable select and the new `NativeSelect` block.

  ## License

  All packages

  - Users are the most real people who had access at the same time in a calendar month. One person with several accounts is one user; scheduled jobs and AI agents do not count.
  - Every organization except non-profits and educational institutions needs a Company License past 3 users, government included. Teaching AwaitIO in a course is free.
  - An agency's clients are counted one by one, also when the agency hosts their apps. An app that many customers pay to use, such as a SaaS, counts all their users together.
  - Only a service for hosting or managing other people's AwaitIO apps is off limits; hosting the apps you built for your clients is fine.
  - A team that cannot afford the license right now can ask for an exception or individual terms at license@awaitio.com.
  - A new Examples section in the license answers common cases. The [pricing page](https://awaitio.com/pricing) shows it word for word.

  ## Migration guide

  From 1.0.0 to 1.1.0.

  <AccordionGroup>
    <Accordion title="awaitio">
      Nothing to change. Update `awaitio` and every `@awaitio/*` package to `^1.1.0` together, so the theme draws the new select.
    </Accordion>
    <Accordion title="@awaitio/select-single">
      Nothing to change in code: the call and its answer stay the same, only the field is now a searchable drop-down. To keep the browser's own `<select>`, install `@awaitio/select-single-native`, register it and call `io.select.singleNative` instead.
    </Accordion>
    <Accordion title="@awaitio/theme-default">
      With `@awaitio/theme-default`, nothing to change. A theme of your own that does not build on the default one has to add a `NativeSelect` block before you use `io.select.singleNative`.
    </Accordion>
    <Accordion title="License">

</Update>

<Update label="1.0.0" description="October 21, 2026" tags={["Core", "Components", "License"]}>
  <img src="/images/changelog/1.0.0.png" style={{ marginTop: 0, borderRadius: 12 }} alt="AwaitIO 1.0.0 release: awaitio and every component at 1.0.0" />

  First stable release. AwaitIO runs internal tools in production, and from now on the API follows semver: breaking changes come only in a new major version.

  ## Core

  `awaitio@1.0.0`

  - New [`maxFailedLogins`](/core/users#too-many-failed-attempts) option: how many failed logins per email lock it, or `false` to turn the lock off.
  - The log out button in the header is a plain icon without a border, so it does not stand out next to the user's name.
  - The app name in the header and on the login page is larger.

  ## Components

  `@awaitio/*@1.0.0`, every component

  - No changes in behavior. They move to 1.0.0 together with the core.

  ## License

  All packages

  - Users are counted across a group of companies, and the free limit of 3 users applies to individuals too.
  - A 30-day evaluation with any number of users.
  - $250 a month for 11–50 users with standard support, and an Enterprise agreement above 50 users.
  - Whoever runs an app pays for it. An agency may buy the license for its client.
  - Components and plugins may be sold.
  - A written answer or a license confirmation on request, at license@awaitio.com.
  - The license is governed by Czech law.

  See [License and pricing](/license).

  ## Migration guide

  From 0.1.0 to 1.0.0.

    </Accordion>

      Nothing to change. Update every `@awaitio/*` package to `^1.0.0` together with `awaitio`.

<Update label="0.1.0" description="October 21, 2026" tags={["Core", "Components"]}>
  <img src="/images/changelog/0.1.0.png" style={{ marginTop: 0, borderRadius: 12 }} alt="AwaitIO 0.1.0, the first release, with the pixel sun" />

  First public release on npm.

  ## Core

  `awaitio@0.1.0`

  - Actions written as async functions that `await` a person's answer through `io`, served together with the UI by the same Node process.
  - Routing, pages, users with login, environments and themes.
  - `ctx` with the user, params, the action, the run id, redirects and loading states.

  ## Components

  `@awaitio/*@0.1.0`, every component

  - Inputs: text, email, URL, textarea, number, boolean, date and datetime.
  - Selects: single, multiple and table, plus confirm.
  - Displays: table, metadata, link, heading, image, Markdown, object and HTML.
  - `@awaitio/layout-basic` and the default theme `@awaitio/theme-default`.
</Update>
