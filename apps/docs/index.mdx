AwaitIO is a backoffice written just like regular API routes. Each action is an async TypeScript function, like a route handler. Instead of reading a request, every `await` on `io` asks a person in the browser and waits for the answer.

There is no frontend to build. The same Node process serves the UI, so there is nothing else to host.

## What you write

```ts actions/accounts/createAccountAction.ts
import { app } from '../../app';
import { constants } from '../../constants';
import { db } from '../../db/db';

export const createAccountAction = app.defineAction({
  name: 'Create account',
  description: 'Opens a 14-day trial for a new store and invites its owner.',
  handler: async ({ io }) => {
    const { name, domain, ownerName, ownerEmail, plan } = await io.group({
      store: io.display.heading('Store', { description: 'How the store is called and where it runs.' }),
      name: io.input.text('Store name', { placeholder: 'Acme Coffee' }),
      domain: io.input.text('Domain', { placeholder: 'acme-coffee.example' }),
      owner: io.display.heading('Owner', { description: 'Gets the invitation and full access.' }),
      ownerName: io.input.text('Owner name'),
      ownerEmail: io.input.email('Owner email'),
      plan: io.select.single('Plan after the trial', { options: constants.PLANS, defaultValue: 'growth' }),
    });

    const trialEndsAt = new Date(Date.now() + 14 * 24 * 60 * 60 * 1000);

    const account = await db.account.create({
      data: { name, domain, plan: plan.value, status: 'trial', monthlyRevenue: 0, ownerEmail, trialEndsAt, createdAt: new Date() },
    });

    await db.user.create({
      data: { name: ownerName, email: ownerEmail, role: 'owner', accountId: account.id, lastLoginAt: null, createdAt: new Date() },
    });

    return { account: account.name, id: account.id, plan: plan.label, trialEndsAt, invitationSentTo: ownerEmail };
  },
});
```

## Bring your codebase

A handler is a plain async function that runs in your own Node process, so everything your app already has works inside it. Bring along:

- **your database**: the Prisma client, the ORM or the queries you already use;
- **your business logic**: the services and rules your product runs on, without copying them;
- **logic shared with your API or GraphQL**: the same functions your resolvers and endpoints call;
- **your internal tools**: scripts, utilities, environment variables and any npm package.

AwaitIO only adds `io` to ask a person and `ctx` to know who it is.

```ts actions/refundOrderAction.ts
import { app } from '../app';
import { prisma } from '../prisma';
import { formatMoney } from '../utils/formatMoney';

export const refundOrderAction = app.defineAction({
  name: 'Refund order',
  handler: async ({ io, ctx }) => {
    const orderId = await io.input.text('Order ID');
    const order = await prisma.order.findUniqueOrThrow({ where: { id: orderId } });
    const reason = await io.input.textarea(`Why refund ${formatMoney(order.total)}?`);

    await prisma.refund.create({ data: { orderId, reason, approvedBy: ctx.user.email } });

    return { refunded: formatMoney(order.total) };
  },
});
```

Nothing has to be wrapped, exported to another service or rewritten: between two `await io` calls it is just your code.
